GOOGLE CLASSROOM  and  GLOBAL COURSE & CURRICULUM BUILDER
==========================================================
Prepared: 17 Oct 2026, against commit 7617120 plus the uncommitted changes

NOTHING HAS BEEN CHANGED OR DELETED. This file lists what CAN be removed,
exactly where, in what order, and what to check afterwards, so that

Every item below was checked by searching the whole project (code, config,

What the two names mean in this code
------------------------------------
  "Google Classroom"
      Admin panel tab "Google Classroom" (components/admin/
      GoogleClassroomManager.tsx), the Google Classroom sign-in modal, the
      Home page "Classroom" button, Classroom OAuth scopes, the Classroom
      API key field, the 'classroom.manage' permission and the
      'classroom_sync' Firestore rule.
      IMPORTANT FACT: none of it talks to Google Classroom. There are no
      Classroom API calls anywhere. The courses, rosters, batch pipeline and
      "AI course wizard" are hard-coded sample data and timers.

  "Global Course & Curriculum Builder"
      The heading of the Admin panel tab "Course Builder"
      (components/admin/CourseBuilderView.tsx:264), its server code
      (lib/course-builder/*, app/api/course-builder/route.ts) and its
      Firestore collections (tenants, programs, units).
      IMPORTANT FACT: unlike Classroom, this one is REAL and is ALSO used by
      two PUBLIC pages: "Degree Programs" and "Unit Syllabuses" load their
      content from /api/course-builder first. Those two pages must be
      changed before the Course Builder is deleted (Part B, step B1).
      (The "AI Course Builder Wizard" inside the Google Classroom tab is a
      different, fake feature; it goes with Part A.)


SUMMARY
-------
  Part A - Google Classroom
    Delete 4 files, edit 7 files, 1 Firestore rule, 1 env example line.
    Visible effect: the "Google Classroom" admin tab, the Classroom API-key
    card and the Home "Classroom" button disappear; Google sign-in stops
    asking for Classroom permission. No working feature is lost.
    Risk: LOW, as long as the ClassroomUser type is moved first (A1).

  Part B - Global Course & Curriculum Builder
    Delete 4 code files (2,802 lines) plus 1 optional agent-skill file,
    edit 4 files, remove 3 Firestore rule blocks, optional clean-up of
    Firestore data.
    Visible effects you must accept:
      1. Staff lose the curriculum editor (programs, units, outcomes,
         assessments, modules, compliance matrix, versioning).
      2. The public "Degree Programs" and "Unit Syllabuses" tabs will show
         the same catalogue the chatbot and Application Form already use
         (data/courses.ts + data/units.ts, or Google Sheets once synced):
         4 degrees and 6 units, instead of the Course Builder's
         1 published program and 3 published units.
         Side benefit: the Unit Syllabuses crash and the "$NaNk/yr" fees
         (working.txt #1, #2) go away, because both come from converting
         Course Builder data.
      3. The Admin panel opens on a different first tab (it currently
         opens on Course Builder).
      4. The unauthenticated "prepare_superadmin" action disappears with
         /api/course-builder (a security improvement).
    Risk: MEDIUM - only because of the two public pages. Follow the order.

  Do Part A and Part B separately (two commits), and run the checks in
  Part C after each.
